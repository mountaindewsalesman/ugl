Design questions

v0.3.1 · groups and prefixes

library 0.3.1dictionary 0.6.0tokenizer scheme 3

Three changes to the language itself, decided by the project owner: coordinated modifiers become one group, prefixes become modifier letters, and closing tags officially pair like parentheses. The pipeline is the same as v0.3.0. The steps that changed are marked.

v0.3.0 · transformer parser

library 0.3.0dictionary 0.6.0tokenizer scheme 2

StepKindWhat it isDetails
WordPieceAlgorithmSplits words into the transformer's sub-word piecesBERT basic tokenizer + greedy longest-match WordPiece, re-implemented in pure Python so it runs in Pyodide; identical to the Hugging Face tokenizer on all 6,674 sampled treebank sentences
Transformer encoderNeural netReads the whole sentence at once; each word sees every other wordELECTRA-small discriminator (14M parameters: 12 self-attention layers, 256 dims, 4 heads), fine-tuned for parsing. A word's vector is a learned weighted mix of all 13 layer outputs at its first piece. Numpy implementation (attention, exact GELU, layer norm) matches PyTorch to 6e-6.
Taggers + arcs + labelsNeural netPart of speech, head word and relation for every wordSame heads as v0.2.0: linear UPOS / Penn / feature taggers, biaffine arc scorer (MLP 400), biaffine label scorer (MLP 100). Trained 20 epochs on 5 UD English treebanks on an RTX 4060 (~25 min). Weights 27 MB in float16.
Tree decodingAlgorithmBest tree whose arcs never crossEisner's O(n³) dynamic program with one root; checked equal to brute force on 200 random cases. English trees are projective, so crossing arcs (like "because" attaching across "mother") are ruled out by construction.
RestructureRulesGives each meaning one tree shape"have to / have got to / be able to / be going to / be supposed to" are rewritten into auxiliaries like "must", so they get the modal letter (have to = u) instead of a verb
SimplifyRulesSplits long sentences into simpler ones with the same meaningTop-level "and" clauses and comma-set-off asides (non-restrictive relative clauses, appositions, participial phrases) become their own sentences; restrictive clauses, but / or / if / because links, and questions stay whole
Quality flagsRulesSays what may be wrong with each sentenceFlags heads the parser is under 60% sure of (except inside names), pronouns with nothing to refer to, words not in the dictionary, words the parser left unattached, unknown prepositions. tools/build_corpus.py keeps only clean sentences for training data (46% of a Wikipedia sample today).
Readable treeRulesThe playground's indented viewEach scope opens a block and its closing tags close it; which tag closes which word is recorded by the decoder's own parser, so the tree always matches how the line is read

Tried and not shipped

  • Sense choice from the parser's own layers: the fine-tuned layers lost word-meaning information (≤ 66.8%, no better than most-frequent-sense). Replaced by the gloss-comparing sense head above.

Known gaps

  • Mass nouns get "a" when decoding ("a food").
  • Uncertain parses are the biggest reason sentences are flagged (38% of a Wikipedia sample).

StepKindWhat it isDetails
TokenizeRulesSplits sentences and words the way the Universal Dependencies treebanks doRegex; splits clitics (don't → do n't, John's → John 's); skips abbreviations when splitting sentences
ParserNeural netTags each word and finds which word it depends on, with the relation namePer word: trained word embedding (100-d), frozen pretrained vectors (spaCy md, reduced to 128-d by PCA, 60k forms), prefix/suffix embeddings, word-shape embedding, and a character CNN (32-d characters, 100 filters, width 3, max-pooled). Then a 3-layer bidirectional LSTM (300 units each way). Heads: linear UPOS, Penn XPOS and morphological-feature taggers; biaffine scorer for arcs (MLP 400) and labels (MLP 100). Trained with PyTorch on an RTX 4060 on 5 UD English treebanks (EWT, GUM, LinES, ParTUT, Atis; about 33k sentences), 50 epochs, Adam. Exported weights (31 MB) run on numpy; training checks numpy and PyTorch agree.
Tree decodingAlgorithmTurns arc scores into a valid treeChu-Liu/Edmonds maximum spanning arborescence with exactly one root; verified against brute force
LemmatizerRulesBase form of each word (ate → eat)lemminflect lookup tables, with clitic rules ('s → be or have)
AnalyzerRulesBuilds who did what to whom, where and whenEach UD relation is handled in exactly one place. Output: Events (predicate, tense/mood letters, subject, object, adverbs, complements, relations) and Entities (head, modifiers, possessor, relative clauses, quantifier, coordination).
CoreferenceAlgorithmReplaces he/she/it/they with what they meanCandidates from the last 2 sentences; matches number, person-ness and gender; prefers subjects and recency; an ordinary pronoun never means its own clause's subject. Unresolved pronouns become n4 (someone) or n3t (the thing).
Sense choiceNeural netPicks which meaning of a word is meantLocal install: BERT-base context vector against per-sense centroids from SemCor, plus a frequency prior (73.5%). Browser: most frequent sense (66.8%).
SerializerRulesThe only code that writes UGLQuantifier scopes outermost, then relations, then the core clause (subject verb adverbs object complements). Coordinated noun phrases stay one group. Frequent names become numbered nouns.
TokenizerAlgorithmUGL text ↔ integer idsOne id per concept in frequency order, one per modifier letter, one per closing tag of a relation verb; rare literals split into 4,000 BPE pieces learned from the corpus
DecoderAlgorithmUGL → EnglishRecursive-descent parser over the UGL grammar, then a realiser (word order, articles, agreement, inflection via lemminflect). No neural net.

What worked

  • Simple sentences round-tripped exactly
  • 0.94 UGL tokens per English word (before tokenizer ids)
  • Frozen, versioned dictionary from day one

Why it was replaced

  • spaCy cannot run in a browser
  • Rules mixed grammar and token spelling, so fixes became special cases
  • 3% of encodings failed to decode; names cost many tokens
